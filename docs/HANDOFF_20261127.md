## 九、方法论：这个项目踩过的坑

### 必须遵守

1. **优先查持久化日志，不要依赖 logcat** —— logcat 只保留几十分钟，本会话多次因此丢失证据。
   - `qqng_exit_trace.log`、`wup_dump.log`、`qqbypass.log` 才是可靠来源
2. **清日志前必须先归档** —— 本会话曾为观察 Turing 清空 `qqbypass.log`，导致被踢前的归因数据永久丢失
3. **证据分级**：A=端到端实测 / B=二进制读出 / C=行为观察 / D=推断（必须标注）
4. **单变量实验**：改一个变量，验证一个结论
5. **官方工具优先**：自写 dex 解析器曾漏 2/3 的调用点

### 已证伪的结论（`docs/CORRECTIONS.md` 有 11 条，别重复）

- ❌「阻断 Turing 上报会让会话掉到 7 分钟」→ Turing 根本不上报
- ❌「Turing 是反检测核心」→ fekit 才是（381 vs 5）
- ❌「wifissid 配置存在就会上报」→ QQ 从不调 getSSID
- ❌「libnative-memory 是检测层」→ 未启用的 APM
- ❌「自杀导致被踢」→ 加了 SuicideGuard 仍被踢
- ❌「k54 来自 ro.board.platform」→ 来自 `ro.product.board`

### 归因工具的正确用法

```
ATTR_PROBE=true / ATTR_DEEP=true
→ FKCALL <fn> mod=<模块>+0x<偏移> d=<深度> act=<fake|real> prop=<名>
```

**这是本项目最有价值的工具。** 但要记得：
- `act=real` 只能发现「没伪造」，**发现不了「伪造值之间互相矛盾」**
- 必须双向检查
